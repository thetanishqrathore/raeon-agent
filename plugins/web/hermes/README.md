# Hermes native web scraper (`hermes` web backend)

A dependency-light, self-hosted **`web_extract` backend** that turns web pages
into clean "fit markdown" — and, on demand, into focused answers or structured
JSON — without any third-party scraping API. It is the in-house, Firecrawl-class
core for Hermes.

It distils the best ideas from two open-source scrapers:

| Idea | Borrowed from | Where it lives |
|------|---------------|----------------|
| Two-tier output: `raw_markdown` **and** pruned `fit_markdown` | crawl4ai | `pipeline.py` |
| Heuristic content pruning (text-density · link-density · tag/class priors) | crawl4ai `PruningContentFilter` | `pruning.py` |
| Main-content location by leaf-score propagation (Readability-style) | trafilatura/Readability | `pruning.py:extract_main_content` |
| Citation / References extraction (`⟨n⟩` markers) | crawl4ai | `mdgen.py:convert_links_to_citations` |
| Aggressive HTML cleanup; preserve `<script type=ld+json>` | ScrapeGraphAI `cleanup_html` | `htmlclean.py` |
| Token-aware chunking + map-reduce LLM extraction | ScrapeGraphAI | `chunking.py`, `llm_extract.py` |
| BM25 relevance pre-filter before the LLM | crawl4ai `BM25ContentFilter` | `bm25.py` |
| Tiered fetch (HTTP → stealth browser) | crawl4ai identity crawling | `fetch.py` |

## Pipeline

```
fetch (httpx → Camoufox on bot-wall/JS-shell)
  → parse + clean (lxml; strip scripts/forms/hidden; harvest JSON-LD; absolutize links)
  → strip obvious chrome (nav/footer/role-landmarks)
  → locate main-content root (leaf-score propagation + semantic/class multipliers)
  → prune residual boilerplate (composite score; protect content-heavy wrappers & headings)
  → markdown: raw_markdown (full) + fit_markdown (pruned)   ← NO LLM up to here
  → [optional] LLM: query → map-reduce answer | schema → structured JSON   (BM25-prefiltered)
```

A **safety net** guarantees we never return near-empty content when the page had
text: pruning that removes too much falls back to relaxed pruning, then to the
unpruned cleaned tree.

## Usage

Select it as the extract backend (no API key needed):

```yaml
# ~/.hermes/config.yaml
web:
  extract_backend: hermes
```

It is also the keyless fallback when no other extract backend is configured.
`lxml` + `rank-bm25` lazy-install on first use (`search.hermes` in
`tools/lazy_deps.py`).

The `web_extract` tool gains two optional params (work with any backend, best
with `hermes`):

- `query`: return a focused answer extracted from the page instead of full markdown.
- `schema`: a JSON Schema → return structured JSON extracted from the page.

## Evaluation

`eval/run_eval.py` scores extraction quality against a verified case set
(`eval/cases.json`, generated by the `hermes-scraper-evalset` workflow; seed set
in `eval/cases.seed.json`):

```
venv/bin/python -m plugins.web.hermes.eval.run_eval            # full (with LLM structured)
venv/bin/python -m plugins.web.hermes.eval.run_eval --no-llm   # deterministic only
```

Metrics: `content_recall` (main content kept), `boilerplate_removal` (chrome
stripped), `quality_f1`, `compression`, and structured `field_accuracy`. The
naive full-page baseline is reported alongside to quantify the value of pruning.

Current results on the 24-case verified set (12 categories × 2):

| | content_recall | boilerplate_removal | quality_f1 |
|---|---|---|---|
| **Hermes** | **0.83** | **0.97** | **0.87** |
| naive baseline | 0.94 | 0.27 | 0.32 |

Structured (schema) extraction field-accuracy: **0.77** (1.00 on
well-structured pages — books/quotes/arxiv; lower only on Hacker News' partial
table-layout content). Perfect (f1≈1.0) on news, docs, GitHub READMEs,
e-commerce, Wikipedia articles & data tables, MDN, and StackOverflow answers;
the long tail (Hacker News comment trees, a few partial bylines) is the same
content that hosted SOTA scrapers also struggle with.
